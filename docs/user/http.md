# LUCE HTTP API + Captive Portal (NET1)

Date: 2026-03-01

## Scope

NET1 provides a TLS-protected HTTPS API surface (state + control routes) and a captive portal UI served from `./data/webapp` on plain HTTP port `80`. HTTPS identity is CSR-based: the device generates and stores its own private key, exports only a CSR, and accepts only a signed certificate matching the local key. If the key or signed certificate is absent, oversized, unreadable, or mismatched, HTTPS logs an explicit refusal and stays unavailable. Use `tls.status` (CLI) or `/api/info`'s `http_state`/`https_running`/`tls_status`/`tls_last_error`/`cert_present`/`key_present` fields to diagnose.

## NVS schema (`http`)

- `http/enabled` (u8, default `0`)
- `http/port` (u16, default `443`) for HTTPS API
- `http/token` (string, required for protected routes)
- `http/tls_key_alg` (string, currently `ec-p256`)
- `http/tls_key_pem` (string, device-generated EC P-256 private key)
- `http/tls_cert_pem` (string, PEM-encoded X.509 certificate signed from the device CSR)
- `http/tls_cert_staged` (string, temporary import buffer used by `tls.cert.*`)
  - The private key is generated by firmware via `tls.keygen`; there is no supported CLI, HTTP, or NVS import workflow for externally generated private keys.
  - PEM bodies are never returned by HTTP. `tls.csr` prints only the CSR; `tls.status` and `/api/info` expose presence, byte counts, status, and certificate metadata.
  - Values larger than the runtime PEM buffers are rejected and reported as `material_oversized`; they are not truncated or logged.

## Certificate Provisioning Boundary

The supported HTTPS provisioning workflow is the same for development and production:

1. Enable HTTP configuration (`http/enabled=1`, `http/token`, optional `http/port`) and boot with serial CLI access.
2. Run `tls.keygen` once on the device. Firmware creates an EC P-256 private key, stores it in `http/tls_key_pem`, and clears any previous certificate.
3. Run `tls.csr` and copy the PEM block between `tls.csr begin` and `tls.csr end`.
4. Sign that CSR with the development CA or production CA.
5. Import the signed certificate over the serial CLI:
   - `tls.cert.begin`
   - `tls.cert.append <one PEM line>` for every certificate line, including `-----BEGIN CERTIFICATE-----` and `-----END CERTIFICATE-----`
   - `tls.cert.commit`
6. Reboot or restart networking. HTTPS starts only after the certificate parses and matches the stored key.

`tls.cert.commit` rejects parse failures, mismatched public keys, and missing staged material. `tls.reset` erases the local key, committed certificate, staged certificate, and key algorithm marker; use it only when intentionally reprovisioning the device.

There is no bundled development certificate, mode switch, alternate route alias, or HTTP route that writes TLS identity material.

```bash
tls.keygen
tls.csr
tls.cert.begin
tls.cert.append -----BEGIN CERTIFICATE-----
tls.cert.append MIIB...
tls.cert.append -----END CERTIFICATE-----
tls.cert.commit
tls.status
```

After commit, `tls.status` should report `workflow=csr key_present=1 csr_ready=1 cert_present=1 ready=1` plus the certificate fingerprint, subject, and issuer.

## Endpoints

- `GET /api/health`
  - minimal public health and service state
- `GET /api/info`
  - requires bearer token in `Authorization: Bearer <token>`
  - includes compatibility fields for legacy consumers:
    - identity/build: `name`, `version`, `strategy`, `sha`, `build`, `uptimeMs`, `uptime_s`
    - relay/sensor: `relays`, `nightMask`, `day`, `threshold`, `light`, `temperature`, `humidity`, `sensor_ok`
    - network: `wifi_ip` and nested `network.{ip,wifiConnected,mqttConnected,ntpSynced}`
    - current HTTP flags: `http_enabled`, `http_port`, `http_state`, `https_running`
    - TLS identity status: `tls_state`, `tls_status`, `tls_last_error`, `key_present`, `csr_ready`, `cert_present`, `cert_fingerprint`, `cert_subject`, `cert_issuer`
- `GET /api/state`
  - requires bearer token
- `GET /api/ota`
  - requires bearer token
- `POST /api/ota/check`
  - requires bearer token; optional URL from query/body:
    - query `url=<https://...>` takes precedence when provided and non-empty
    - otherwise plain-text body payload is used when non-empty
    - when neither source provides a URL, queued check runs with configured/default source
  - response payload includes:
    - `status` = `queued`
    - `source` = `query|body|default` (effective URL source resolution)
- `PUT /api/ota/check`
  - alias of POST behavior for update checks; requires bearer token
- `GET /api/version`
  - returns firmware version/identity details
- `GET /api/leds/state`
  - requires bearer token; returns current LED state and manual override masks
- `PUT /api/leds/state`
  - requires bearer token; command LED manual overrides:
    - body/query `value=0..7` sets manual state mask for LEDs `0..2`
    - body/query `value=auto|off|on|blink|fast|slow|flash` applies mode to all LEDs `0..2`
- `GET /api/leds/state/0` (same for `/1`, `/2`)
  - requires bearer token; returns current state for selected LED index and manual value (`null` when auto mode)
- `PUT /api/leds/state/0` (same for `/1`, `/2`)
  - requires bearer token; command selected LED index:
    - body/query `value=0|1|on|off|true|false|auto|blink|fast|slow|flash` sets mode for that index
- `GET /ws`
  - websocket endpoint (available on HTTPS API server and captive HTTP server)
  - handshake sends an immediate state snapshot
  - server pushes periodic state snapshots with relay/night/sensor fields (`type`, `tstamp`, `state`, `night`, `day`, `threshold`, `light`, `voltage`, `temperature`, `humidity`, `sensor_ok`)
- `GET /`
  - serves `./data/webapp/index.html`
- `GET /index.html`
- `GET /app.css`
- `GET /script.js`
  - all unresolved paths on captive HTTP fall back to `index.html` for SPA-style navigation

## Runtime behavior

- Starts only when Wi-Fi IP is present and config is enabled.
- HTTPS API server starts on `http/port` (default `443`) and registers `api/*` endpoints.
- HTTPS refuses to start when the local key is missing, signed certificate is missing, certificate/key material is unreadable or oversized, or the certificate does not match the local key.
- Captive portal starts on plain HTTP port `80` when enabled, unless `http/port` is also `80`.
- Starts/stops with Wi-Fi state transitions.

## Smoke checks

- Run `./scripts/http_api_smoke.sh --host https://<device-ip> --token <http-token>` to verify:
  - GET endpoints for health/info/version/ota.
  - POST/PUT `/api/ota/check` accepted.
  - unsupported methods return `405`.
  - unauthenticated protected endpoints return `401` (unless `--skip-unauth`).
  - The smoke script uses `curl -k`; it validates endpoint behavior, not CA trust or hostname identity.
- Or run the wrapper: `./scripts/luce.sh http-smoke --host https://<device-ip> --token <http-token>`.

## Logging

- `[HTTP]` logs for API and portal startup.
- `[HTTP][CAPTIVE]` logs for portal startup and request fallbacks.
- `tls.status` reports `workflow=csr`, `https_running`, `tls_status`, `last_error`, cert/key presence, byte counts, and certificate metadata without logging private key or certificate PEM bodies.
